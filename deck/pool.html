ERC-8004 reputation, measured

Zhao et al., “Can Trustless Agents Be Trusted?” Reviewers flagged for coordinated Sybil behavior: 73.5% on Ethereum, 59.2% on BSC, 90.6% on Base. The paper’s point: a public feedback registry is not a trust signal when the reviewer set can be manufactured.

arxiv.org/html/2606.26028v2

The spec already warns

ERC-8004 getSummary: client addresses must be provided. Results without that filter are subject to Sybil and spam. Aggregation of reviewer reputation is left off-chain. The standard publishes the signal. It does not refuse a payment.

The rule · one function, no client argument

decidePayout reads delivery, two proofs, and nothing the browser asserts.

if not delivered            → hold
if either proof is missing  → hold
if issuer ≠ sandbox World   → hold     (not-world)
if subject A = subject B    → hold     (same-human, refused)
else                        → release  (counted = reward)

Issuer that counts: https://sandbox.auth.world.org. A local issuer named local-sandbox stays unpaid even when the two subject strings differ. Replacing the buyer subject with a second World subject releases the same job and clears the refused total.

Where the World ID token enters

The subject is taken from an ID token. The device code never reaches the page.

1 · CodeServer POSTs the device-authorization endpoint with HTTP Basic. A secret in the form body is rejected by the issuer. The page receives only the user code.
2 · PersonThat person approves the code in the sandbox World App. Pending and denied pulls attach nothing.
3 · CheckOne token pull. RS256 against the JWKS. Issuer, audience, and expiry have to match. Then we store subject and issuer.
4 · SettleBoth seats must carry that issuer. The subjects must differ. The decision is recomputed from the stored proofs.

Discovery, fetched 26 Sep 2026

Issuer https://sandbox.auth.world.org. Device endpoint /api/v1/device_authorization. Token endpoint /api/v1/token. JWKS on the well-known document. Signing alg RS256. Subject type pairwise. Grants include urn:ietf:params:oauth:grant-type:device_code. Scope openid.

sandbox.auth.world.org/.well-known/openid-configuration

What the browser cannot supply

Post, deliver, and claim accept a subject, an issuer, released, and differentHumans. Those fields are not copied onto the job. There is no /proof route. Pull without a server-held device code returns an error and stores nothing. On Vercel the job, the device code, and the user code ride in an HMAC-signed httpOnly cookie so the escrow survives the next request.
