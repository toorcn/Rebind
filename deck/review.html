What we would implement · from the plugin README

Register a sandbox OIDC client, then verify the token on our server.

  • Developer scope developer-portal:manage registers the app. Callback must be HTTPS. Localhost is rejected.
  • Client secret stays in server env. It is never sent to the browser and never pasted into chat.
  • Our existing POST /rebind/live/start calls https://sandbox.auth.world.org/api/v1/device_authorization.
  • POST /rebind/live/pull checks RS256, issuer, audience, and expiry on the ID token, then stores iss|sub.
  • Denied, expired, or a client “validated” flag never writes that field, so K2 cannot pay.

Discovery read live: sandbox.auth.world.org/.well-known/openid-configuration · device grant, token endpoint, JWKS, acr orb-v3, pairwise subject.

What we would not build · same sources

The blog’s free trial and AgentBook-as-opcode are the wrong product.

  • AgentKit free-trial mode (x402 docs, and the 17 March essay) is a hard no. We do not sell “five free requests.”
  • IDKit human-in-the-loop as app login is a hard no. The protected action stays the paid grant.
  • We do not ship an AgentBook mainnet opcode. Issues #37 and #23 are the reason revoke matters, not a patch we claim to have merged.
  • A Vercel serverless function alone will drop the in-memory registry between calls. Live OIDC also needs one stable HTTPS callback.

x402 guide: github.com/worldcoin/agentkit/blob/main/x402/DOCS.md · HITL: docs.world.org/agents/human-in-the-loop/integrate
